# C Repair クイックスタート

[English](user-guide.md)

Scanの前に[ローカル](#ローカル自分のコンピューターでモデルを使う)か[OpenRouter](#apiopenrouterを使う)を設定します。設定済みなら、そのまま以下へ進んでください。

1. C Repairビュー（結果の表示中は **…** メニュー）の **Open practice sample**。新しい `quick-start.c` とこのガイドが並んで開きます。
2. **コード内で右クリック → Scan & Fix Current File**。修正案を待ちます。Context Reviewが出たら宣言を確認し、**Confirm & Scan** で続けます。APIではOpenRouterへ送信し、有料モードではトークン費用が発生します。
3. **差分と、C RepairビューのProposed fixの下の検証結果**を読みます。添字の下限・上限を確認し、範囲外では `-1` を返す修正かを見ます。
4. **差分のツールバー → Accept Repair（✓）またはReject Repair（⊘）**。Acceptは練習用ファイルを編集するので **Ctrl+S**（Macは **⌘S**）で保存します。Rejectなら変更しません。
5. **`quick-start.c` の通常の編集タブへ戻る → 右クリック → Scan Current File**。元の指摘が引き続き表示されるかを確認します。

**コードを変更するのはAcceptです。** Scanは検出、Scan & Fixは検出と修正案の生成です。毎回、プロジェクト外に新しい練習用コピーを作ります。開くだけでは推論は始まりません。

サンプルは添字を確認せず `values[index]` を読んでいます。差分は左右に並ぶ場合と、1画面内に表示される場合があり、結果はモデルにより変わります。format・compileのfailはAcceptできません。警告は内容を読んで判断してください。compileがskippedなら[必要環境](../README.md#requirements)を参照してください。

ガイドはビューの **本のアイコン**、または **歯車 → Setup → Commands → Quick start & user guide** で開けます。**Open practice sample** はビューの **…** メニューと **歯車 → Setup → Commands** にもあります。

## ローカルまたはAPIを設定する

アクティビティバーから **C Repair** ビューを開き、以下のどちらかを選びます。

### ローカル：自分のコンピューターでモデルを使う

1. 空のC Repairビューで **Use a local model** を選びます。**歯車 → Setup → Local Setup → Set up or start local model** からも開始できます。
2. モデルを選びます。量子化とメモリ設定は自動設定されます。ダウンロード容量と保存先を確認し、**Download and start** を選びます。既存モデルでは **Start local model** を選びます。
3. モデルの準備完了メッセージが出たら、CファイルをScanします。

この操作でモデル・推論エンジン・Pythonブリッジを準備します。APIキーや、初回に別途 **Set Up Bridge** を行う必要はありません。初回ダウンロードにはインターネット接続が必要です。

対応環境、既存モデル、必要メモリと調整方法は[ローカルモデル設定ガイド](local-models.ja.md#初回セットアップ)を参照してください。拡張を更新しても保存済み設定は維持されます。セットアップをキャンセルした場合や失敗した場合は、**Use a local model** または **Set up or start local model** をもう一度選んで準備を完了してください。

### API：OpenRouterを使う

1. C Repairビューで **Connect OpenRouter** を選びます。ブラウザーで承認し、表示された一時コードをVS Codeの入力欄へ貼り付けます。既存キーを使う場合は **歯車 → Setup → Api Key → Set API Key manually** を開きます。
2. 選択画面が出たら **Use the preset model** または **Try the free model first** を選びます。Presetはこの版のモデル・提供元の設定、Freeは共有の無料モデルを使います。自分でモデル・提供元を指定する場合は、**歯車 → Models & Routing → Model Mode** で **Custom** を選びます。APIのどのモードでもOpenRouterキーが必要です。
3. 初回に **歯車 → Setup → Commands → Set Up Bridge** を実行します。ブリッジの準備完了メッセージが出たら、CファイルをScanします。

`crepair.bridge.pythonPath` に自分の環境を指定した場合は、[カスタムブリッジの更新手順](local-models.ja.md#カスタムpythonブリッジ)に従います。Set Up BridgeはC Repair専用環境を更新するため、カスタム環境は別途更新してください。

APIでは、Scanするコードと補助宣言をOpenRouterおよび選択された提供元へ送ります。キーはVS CodeのSecretStorageに保存されます。有料利用の費用はモデルとトークン量により異なり、Freeには待ち時間や利用制限があります。

ローカルからAPIへ切り替える場合は、キーの接続に加えて **Model Mode** を **Preset**、**Free**、**Custom** のいずれかへ変更してください。キーの接続だけでは、設定済みのローカルモードは切り替わりません。

## CファイルをScanする

1. エディタで1つの `.c` ファイルを開きます。
2. エディタ内で右クリックし、違反検出のみなら **Scan Current File**、修正案の生成も行うなら **Scan & Fix Current File** を選びます。
3. **Context Review** が開いた場合は、推定された宣言を確認し、通知の **Confirm & Scan** で続行します。通知を閉じた場合は、コマンドパレットの **C Repair: Confirm Context & Scan** から続けられます。

Context Reviewは、このファイルだけでは解決できない外部の型・関数・マクロに作業用の宣言を補います。誤った宣言は修正してから続行してください。**補助宣言はソースファイルへ書き込まれません。**

レビューを省略した場合やcontextが不完全な場合、未解決の仮定に依存する結果になり、一部の検証が省略されることがあります。検出結果とともにcontextの警告を確認してください。

C Repairビューに関数ごとの検出結果が表示され、エディタの波線でも場所を確認できます。**Scan Current File** は修正案を生成しません。個別に修正する場合は、違反の **Generate Repair** を選びます。

## 検出結果と検証結果を読む

検出結果には、対象関数・CERT Cルール・説明が表示されます。修正候補を展開して検証結果を確認するか、差分を開きます。

各候補には5つの検証があります。

| 検証 | 確認する内容 |
| --- | --- |
| format | 修正結果が利用可能な形式か |
| compile | 利用可能なコンパイル検証を通るか |
| violation_removal | 再検出で対象違反が除去されたか |
| semantic | 元の動作を保っているとモデルが判断するか |
| regression | 検証結果から新たな問題がないと判断できるか |

**pass**、**fail**、**skipped** は異なります。skippedは、その検証で正しさを確認できていません。コンパイラーや必要な宣言が利用できない場合などは、compileが省略されます。

**formatまたはcompileがfailならAcceptできません。** violation_removal・semantic・regressionの警告は、明示的に確認してからAcceptできます。警告を上書きする前に根拠を読んでください。

検証項目や差分内の検証メッセージをクリックすると詳細を確認できます。検証が通ってもプロジェクト全体の正しさを保証しません。また、検出が0件でも安全性の証明にはなりません。

## 修正をレビューして適用する

候補の差分を開きます。左右表示では左が元のコード、右が修正案です。インライン表示では削除行と追加行が1画面に表示されます。差分のツールバーで次の操作を選べます。

| 操作 | 結果 |
| --- | --- |
| Accept | この修正案をファイルへ適用する |
| Reject | ファイルを変更せず、却下を記録する |
| Regenerate | この違反の修正案を再生成する |
| Next | 採用せずに次の候補へ進む |

差分と検証結果を読んでから操作を選びます。C Repairビューの **Accept All Reviewed** は、レビュー済みで適用可能かつ競合のない候補をまとめて適用します。レビューや、候補ごとの警告確認を省略する操作ではありません。

一部の修正は、ファイル外の変更も必要です。関数の引数が変われば呼び出し側の更新が必要になり、安全な文字列コピーには呼び出し側で保持するバッファ容量が必要な場合もあります。修正の出発点としてAcceptする場合は、必要な変更を自分で仕上げてプロジェクトを確認してください。

適用されるのは採用した修正だけです。補助contextは混入しません。採用した修正に必要なincludeは追加される場合があります。

## 再Scanとレポート出力

Acceptや手動編集の後は、**Scan Current File** で更新後のファイルを検出します。コードが変わると以前の結果はstaleになり、前回Scan時点の結果であることが示されます。

C Repairビューのツールバー、または **歯車 → Setup → Commands** の **Export Repair Report** から、今回の検出・検証・採否をMarkdownで保存できます。レポートにはコードの差分が含まれることがあるため、保存先と共有先を選んでください。

C Repairは1ファイルずつ解析し、1関数につき1件の違反を扱います。必要なプロジェクト全体の変更を仕上げ、通常のビルドやテストも実行してください。

## 設定変更とエラーへの対処

- **ローカルモデル・Reasoning・メモリ・トークン：** **歯車 → Setup → Local Setup → Local model settings** で変更し、**✓ Apply changes** を選びます。[ローカルの設定とトラブル対応](local-models.ja.md#困ったとき)を参照してください。
- **APIのモデル・提供元・Reasoning：** **歯車 → Models & Routing** で変更し、C Repairが案内する再起動操作でブリッジへ反映します。API設定はローカル推論の設定を変更しません。
- **include不足：** **歯車 → Scanning & Context → Compile Include Paths** にプロジェクトのヘッダーディレクトリを設定して再Scanします。
- **ブリッジの準備エラー：** 表示された問題を解決してセットアップを再実行します。旧版から更新した後は、ローカルでも **Set Up Bridge** でブリッジを更新できます。**View → Output → C Repair** で詳細を確認できます。
- **検出・生成を止める：** 進捗通知のCancelを選びます。ローカルモデルは **Stop Local Model** でメモリを解放し、次のローカル操作で再ロードされます。

状態表示にはセッションのトークン量と、APIでは取得できる場合に概算費用が表示されます。小さなファイルでもReasoningに時間がかかることがあります。コードの大きさだけで生成予算を判断せず、設定ガイドを使って調整してください。
